---
name: functional-review
description: "Validate acceptance criteria through runtime and exploratory checks and record reproducible evidence without changing product code."
---

Read requirements, acceptance criteria, developer handoff and technical-review status. Map each criterion to a runtime check, environment and expected result. Exercise risk-based happy paths, edge cases and failures using the application's actual interface. Report PASS, FAIL or NOT VERIFIED per criterion, with exact steps, observed behavior and useful evidence. Separate product defects from unavailable infrastructure. Do not edit product code or alter acceptance criteria; evidence files may be written under evidence/ or reports/. Do not treat mocked tests as proof of a live integration. Respect project-specific tracker transitions and existing authorization.
